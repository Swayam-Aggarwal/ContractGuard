
# Demo Store API Fixtures

## 1. Overview

The Demo Store fixtures are synthetic OpenAPI specifications used to demonstrate specification ingestion, version comparison, compatibility analysis, and change-impact reporting in ContractGuard.

Two versions are provided:

| File | Role | API Version |
|---|---|---|
| `demo-store-v1.yaml` | Baseline | 1.0.0 |
| `demo-store-v2.yaml` | Candidate | 2.0.0 |

Both fixtures use OpenAPI 3.0.3.

## 2. Comparison Direction

Use `demo-store-v1.yaml` as the baseline and `demo-store-v2.yaml` as the candidate.

ContractGuard evaluates whether the candidate provider contract preserves compatibility for consumers built against the baseline.

Ruleset:

`CG-COMPAT-1.1`

## 3. Expected Compatibility Changes

The fixtures demonstrate changes including:

| Component | Change | Expected Classification |
|---|---|---|
| `Product.price` | `number` changed to `string` | `BREAKING` |
| `Product.description` | Response property removed | `BREAKING` |
| `Product.stock` | Response property removed | `BREAKING` |
| `Product.categoryId` | Optional property added | Generally `NON_BREAKING` under the open-object assumption |

The actual findings, affected operations, classifications, and analysis status are generated by the compatibility engine.

## 4. Using the Fixtures

1. Open a ContractGuard project.
2. Upload `demo-store-v1.yaml`.
3. Upload `demo-store-v2.yaml`.
4. Select version 1.0.0 as the baseline.
5. Select version 2.0.0 as the candidate.
6. Run the comparison.
7. Inspect compatibility findings and affected operations.
8. Review linked test cases and coverage information.

## 5. Important Notes

- These specifications contain synthetic demonstration data.
- They are not representations of a real production API.
- Expected changes are illustrative; executable analyzer tests remain the source of truth.
- A complete comparison does not prove runtime compatibility.
- Regression execution is restricted to recognized, server-controlled Demo Store fixtures.
- Uploaded specification server URLs must never be treated as execution targets.
